# 2026-11-17

## 修复新增功能的 UI（错题本高频错误 + 数据统计）

**背景**：`main` 上新增了 SRS 复习（storage.js 的 interval / nextReview / totalErrors / wrongSpellings）与「数据统计」导航项，但 UI 没跟上，且沿用了未定义的设计变量。

**根因**
1. 高频错误的红字用 `var(--wrong)`、灰字用 `var(--muted)`，而设计 token 叫 `--negative` / `--ink-3` → 声明无效，红字退化成继承色，看起来完全没生效。
2. `.spell-chip` 直接包裸文本 + `<span>`，`inline-flex` 的 gap 把每个字母当 flex item，字母被拉开（"m o u u u"）。
3. 数据统计只有 `<button data-target="view-stats">`，DOM 里没有 `#view-stats` → 点击时 `getElementById(...).classList` 抛 TypeError，整块视图打不开。
4. practice.js 新代码用 `els.modeTag.className = "mode-tag ..."` 覆盖掉了 `.stage-kicker`，模式标签丢样式；并用 `els.hint.style.color = "var(--muted)"` 绕过 `data-tone`；emoji 🎧 / ☁️ / 🎉 回流。
5. 列表操作按钮写成 `.btn.btn-icon`（`.btn-icon` 不存在）→ 套上 `.btn` 的 44px 高、120px 最小宽，按钮变成大块。

**改法**
- 新增 `#view-stats`：4 个 stat-tile（已掌握 / 错题本 / 今日已学 / 累计错误）+ 今日进度条 + 复习间隔说明；`renderStats()` 统一渲染。
- 错题本改用类：`.list-item--stack`、`.list-meta`、`.list-meta-value`、`.list-sub`、`.spell-chips`、`.spell-chip`、`.spell-word`、`.spell-mark`、`.spell-count`；错字用 `--negative` + `font-weight:700`（等宽栈只有 400/700，500 会被合成为常规，实测无加粗效果）。
- `highlightMistake` 输出加 `escapeHtml`（输入来自用户，避免 innerHTML 注入）。
- 恢复 `setMode()` / `setHint()` / `stageSteps.dataset.stage`；stage 4 用 `data-mode="due"`（琥珀点）区别于错题复习的 `review`（红点）。
- 操作按钮恢复 `.icon-btn` + Lucide `#i-volume` / `#i-trash`；数据统计导航用新增的 `#i-chart`。
- 已掌握列表新增「下次复习 11 月 24 日」元信息，对应新的间隔复习。
- 移动端 `.daily-track` 的 `flex:1 1 100%` 只在 `.stats` 下生效——它被 column flex 的 `.stat-goal` 继承时高度被压成 0，导致进度条消失。

**验证**：1440×900 与 390×844 渲染，`docW===vw`，6 个 tab 全部可见；实测在听写模式连错两次 → 存储 `wrongSpellings:{mous:2}` → 错题本 chip 显示 `mous_` 且 `_` 为 `rgb(176,64,58)` / 700；无 JS 异常（仅 `/api/sync` 404，无 Worker 时预期）。

**遗留**：PWA 图标仍是旧的棕色旋纹；`js/` 里代码注释还有 👈/👇/🌟 之类 emoji（仅注释，不在界面）。

## 重排错题本 / 统计页 + 重做图标（第二轮）

**用户反馈**：错题本的高频错误「没体现出具体的错误字母」，统计页「挤压在一起太丑」，并要求按参考插画（紫色播放器 + E WORD CARDS 卡牌 + Charlotte/Fin 签名）重做图标。

**关键发现**：用户截图里的页面**完全没有新样式**（chips 无边框、统计页是纯文本行），但 DOM 是新的 → 说明 `styles.css` 被缓存，只加载了新的 HTML/JS。已在 `<link>`/`<script>` 上加 `?v=4` 做缓存失效，并在交付说明里提示硬刷新。

**错题本改成卡片网格**：`.list-grid`（auto-fill minmax(340px,1fr)）+ `.word-card`；高频错误不再是文字，而是**逐字母格** `.cell`：正确字母墨色、拼错字母红字+红底+红框（`cell--wrong`）、漏打位置虚线空格（`cell--miss`，`title="漏打 x"`）。cell 用固定 `width:22px`（不是 min-width），否则不同行宽度不一致、右侧「N 次」不对齐。

**统计页**：改为 hero（今日已学 56px 琥珀数字 + 进度条）→ 双栏（近 7 天柱状图 + 词库概览行表）→ 脚注。柱状图数据来自 `Storage.getDailyHistory()`（新增，读当天 key 的 daily 记录），绘图区 `border-bottom` 做基线，今天那根用琥珀。**坑**：`.stat-bars` 用 `flex:1` 在 auto 高度的 column 里会把高度算成 0（移动端柱状图全塌），必须给固定 `height`。

**图标**：`icon.svg`（大尺寸，含卡牌层叠、两处胶带、右侧奶白标签条 + 字母 E + 三条细线）与 `icon-small.svg`（16/32/48 用，去掉胶带与细线、加粗笔画）。字母 E 用矩形拼成，不用 `<text>`——Chrome 光栅化 SVG 文字会带 LCD 彩边。用 Chrome headless 逐尺寸截图生成 PNG，再用 Python 手工写 PNG-in-ICO 容器生成多尺寸 `favicon.ico`。侧栏品牌标识同步换成 20px 的简化卡片（卡片轮廓 + 标签分割线 + 琥珀短线）。

**验证**：1440/390 双视口 `docW===vw`，6 个 tab 全部可见；错字格计算样式 `rgb(176,64,58)` / 700 / 红底；无 JS 异常（仅 `/api/sync` 404）；图标全部 200。
